What setup looks like

It runs on your machine with your own Google OAuth client. Nothing is hosted or shared.

  • Claude CodeThe server registers with it, and its prompts carry the approvals.
  • Node.js 26 or laterIt runs its sources directly, with no build step.
  • Your own Google Cloud OAuth clientA free project you own. The folder has a step-by-step guide.
  • A keyring, or private filesRefresh tokens go in the system keyring on Linux, or in files only you can read.

Questions

Can Claude approve a send for itself?

No. The approval is a prompt shown by the MCP client, which the model never sees or answers. On newer clients the approval is also tied to the exact prompt text that was shown.

What if I ask it to use the wrong account?

The prompt names the account and the reason before anything happens, so you can say no. Accounts on the block list are refused whatever you ask.

Does it read my mail in the background?

No. There is no watching, polling, push or schedule. It acts only when you ask.

Where are my tokens?

In the system keyring by default, encrypted at rest and unlocked with your session, or in files only you can read on systems without one.

Can mail content trick it?

Every read result is labelled as untrusted content, and any change it might suggest still needs your approval.
